# 🔗 SQL Joins

> **Learning Goal:** Learn how to combine data from multiple tables to build a complete view of your business.

---

## 🧐 Why Join?

In professional databases, data is "Normalized". Instead of saving the Store Location and Store Manager for every transaction, we save a `store_id` and look up the details in a separate `stores` table. 

This saves space and ensures data consistency.

---

## 1️⃣ The Common Join Types

| Join Type | Description |
|-----------|-------------|
| **INNER JOIN** | Returns records that have matching values in both tables. |
| **LEFT JOIN** | Returns all records from the left table, and matched records from the right. (Most common!) |
| **RIGHT JOIN** | Returns all records from the right table, and matched records from the left. |
| **FULL JOIN** | Returns all records when there is a match in either table. |

---

## 2️⃣ How to Write a JOIN

To join tables, you need a **Common Column** (usually an ID).

```sql
SELECT 
    t.txn_id, 
    t.amount, 
    s.location, 
    s.manager
FROM transactions t        -- 't' is an alias
JOIN stores s              -- 's' is an alias
ON t.store = s.store;      -- The common link
```

---

## 3️⃣ Left Join vs Inner Join

Imagine we have a new store that hasn't made any sales yet.
- **INNER JOIN**: This store won't show up in a sales report.
- **LEFT JOIN**: The store shows up, but the sales amount will be `NULL`.

Analysts usually prefer **LEFT JOIN** to ensure they don't accidentally lose data from the primary table.

---

## 🏗️ Real-World Example: Manager Performance

Find the total revenue generated by each Manager.

```sql
SELECT 
    s.manager, 
    SUM(t.amount) as total_managed_sales
FROM stores s
LEFT JOIN transactions t ON s.store = t.store
GROUP BY s.manager
ORDER BY total_managed_sales DESC;
```
